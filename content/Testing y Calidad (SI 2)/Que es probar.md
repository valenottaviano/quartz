- La actividad de **probar** se encuentra en la fase de análisis y diseño de las pruebas.

### Etapa de análisis de las pruebas

- Se trata de entender el sistema, sus componentes, sus interacciones
- Identificamos escenarios de prueba, osea "que probar"
- Tratamos de pensar como usaría un usuario potencial el sistema.
- Pensamos todo aquello que debería y no debería ocurrir en el uso del sistema.


### Caso de prueba

> Conjunto de ==pre condiciones, entradas y resultados esperados==, desarrollado para ==dirigir la ejecución== de un elemento de prueba, para cumplir con los objetivos de la prueba.

### Buenas prácticas para un caso de prueba

- Deben completarse todos los campos posibles del caso de prueba
- Los pasos deben redactarse como acciones
- El caso de prueba debe ser fácil de seguir
- Cada click o acción debe quedar registrado
- Cada paso debe tener su resultado esperado asociado
- Utilice nombres correctos para hacer referencia a menús, pantallas, opciones, botones, etc.
- Cualquier persona debería ser capaz de ejecutar tus casos de prueba
